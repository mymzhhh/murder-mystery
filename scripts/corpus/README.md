# 语料普查与蒸馏准备

给 `D:\play game\剧本杀剧本资源合集`（24 GB / 10489 个文件 / 225 个剧本）做**结构普查**，
产出「哪些本值得投入解析成本」的合格清单。产物见 `../../docs/剧本语料-合格清单.md`。

## 为什么先普查再解析

全量解析 24 GB 不现实（近 8000 张图 + 1000 个 PDF，光 OCR 就是几小时起，且 OCR 错字会污染统计）。
先花几分钟读**文件结构 + docx 文本 + PDF 页数**，就能把"值得解析的本"从 225 个收到 20 上下。

## 执行顺序

```powershell
$py = "C:\Users\34141\AppData\Local\Programs\Python\Python312\python.exe"
$env:PYTHONIOENCODING = "utf-8"

& $py scripts\corpus\01-census.py        # 主普查 → docs/剧本语料-合格清单.csv
& $py scripts\corpus\05-rescue-doc.py    # 把「仅 .doc」从不合格里救回（A- 档）
& $py scripts\corpus\02-enrich-clues.py  # 补线索文件字数/轮次（只处理 A 档）
& $py scripts\corpus\03-dedupe.py        # 内容指纹去重 → docs/剧本语料-重复本.csv
& $py scripts\corpus\04-make-list.py     # 生成人读版清单 → docs/剧本语料-合格清单.md
```

依赖：`python-docx`、`pypdf`（系统 Python 3.12 已装）。

## 分档口径

| 档位 | 含义 |
|---|---|
| A1 | docx 文本 + **线索也是 docx** —— 第一优先 |
| A2 | docx 文本，线索在图片/PDF 里 |
| A- | 仅 .doc 旧格式，转 docx 后可用 |
| B | 文本型 PDF（能抽中文），MinerU 可直接转 |
| C | 扫描 PDF，需 OCR |
| D | 纯图片，需 OCR |
| X | 不合格（英文/无正文文件） |

## 踩过的坑（别重复）

1. **不要用「A1/B1 线索编号」当判据** —— 源剧本没有编号，那是我方导入脚本自己编的。
   344 的《线索.docx》是按人物分组的「1. 2. 3.」列表。
2. **不要只用「编号行数」判线索** —— 039-愤怒的葡萄 用的是「第N轮的秘密线索 + 按这条线折叠」
   的分页式排版，编号行数为 0 但线索齐全。要看**线索文件字数**。
3. **.doc 不是没有内容** —— python-docx 读不了 Word 97-2003 二进制格式，
   10 个剧本曾因此被判成不合格，实际内容齐全（A- 档）。
4. **语料里有重复本** —— 144/197 万灵血、141/199 校园不可思议事件等 4 组，
   按「文件名+大小」指纹能查出来，统计前必须去重。
5. **供词式短角色本会被 1500 字阈值漏掉** —— 如 008-死亡致意 的角色本是「XX 供词.docx」，只有几百字。
