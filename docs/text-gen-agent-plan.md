# 文本生成 Agent 设计方案

## 1. 项目概述

构建一个基于 LLM 的文本生成 Agent，用户输入需求描述后，Agent 能理解意图、拆解任务、生成高质量文案，并支持多轮迭代优化。
模型使用deepseek-v4-flash
对应的apikey见项目 `.env` 中的 `DEEPSEEK_API_KEY`（请勿在文档中记录明文密钥）

## 2. 核心架构

```
┌──────────────┐    ┌──────────────────┐    ┌─────────────┐
│   Web 前端    │───▶│   后端 API 服务   │───▶│ DeepSeek API │
│  (用户交互)   │◀───│  (路由/编排)      │◀───│  (文本生成)   │
└──────────────┘    └────────┬─────────┘    └─────────────┘
                             │
                      ┌──────┴──────┐
                      │  SQLite/JSON │
                      │  (历史记录)   │
                      └─────────────┘
```

## 3. 技术选型

| 层级       | 技术                        | 理由                           |
| ---------- | --------------------------- | ------------------------------ |
| 前端       | HTML + CSS + vanilla JS     | 轻量，无框架依赖，快速开发     |
| 后端       | Node.js + Express           | JS 生态完善，异步处理友好       |
| LLM        | DeepSeek API (OpenAI SDK)    | 文本生成质量高，支持长上下文     |
| 数据存储    | JSON 文件 (后续可换 SQLite) | 简单，零配置，适合 MVP          |

## 4. 核心模块设计

### 4.1 意图解析模块 (Intent Parser)

Agent 收到用户输入后，首先分析用户意图，提取关键信息：

- **文本类型识别**：营销文案 / 技术文档 / 社交媒体 / 邮件 / 演讲稿 / 创意故事 / 自定义
- **关键要素提取**：主题、目标受众、风格、字数/长度、关键词、语气(Tone)
- **缺失信息追问**：如果关键信息不足，Agent 主动向用户提问补充

```javascript
// 意图解析示意
{
  "textType": "marketing",       // 文本类型
  "topic": "新产品发布",          // 主题
  "audience": "年轻白领",         // 目标受众
  "style": "活泼",               // 风格
  "wordCount": "200-300字",      // 长度要求
  "keywords": ["效率", "智能"],   // 关键词
  "tone": "enthusiastic",        // 语气
  "specialRequirements": []      // 特殊要求
}
```

### 4.2 模板系统 (Template Engine)

预置多种文本类型模板，包含结构化 Prompt，确保输出质量和一致性：

- **营销文案模板**：AIDA 模型（Attention → Interest → Desire → Action）
- **社交媒体模板**：平台特性适配（小红书、微博、公众号、Twitter 等）
- **邮件模板**：正式/半正式/非正式，包含主题行、正文、签名
- **技术文档模板**：概述 → 详细说明 → 示例 → 注意事项
- **故事创作模板**：起承转合结构，人物/场景/冲突/结局

每个模板本质上是一个精心设计的 System Prompt，引导 DeepSeek 按特定结构输出。

### 4.3 生成流水线 (Generation Pipeline)

```
用户输入 → 意图解析 → 模板选择 → Prompt组装 → LLM调用 → 结果后处理 → 输出
                                                          │
                                                    ┌─────▼─────┐
                                                    │ 多轮优化循环 │
                                                    └───────────┘
```

### 4.4 多轮优化引擎 (Refinement Loop)

用户可对生成结果提出修改意见，Agent 将修改意见连同历史上下文一起发送给 LLM：

- **单点修改**：改某个词、调整语气
- **结构重写**：重新组织段落
- **风格切换**：同一内容换成不同风格
- **版本对比**：保留多版本供用户选择

### 4.5 历史管理 (History Manager)

- 按会话组织历史记录
- 支持查看、恢复、删除历史会话
- 使用 JSON 文件存储，格式如下：

```json
{
  "sessionId": "uuid",
  "createdAt": "2026-05-08T10:00:00Z",
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ],
  "metadata": {
    "textType": "marketing",
    "topic": "新产品发布"
  }
}
```

## 5. API 设计

| Method | Path                    | 说明                 |
| ------ | ----------------------- | -------------------- |
| POST   | /api/generate           | 生成文本             |
| POST   | /api/generate/refine    | 基于反馈优化文本      |
| GET    | /api/sessions           | 获取历史会话列表      |
| GET    | /api/sessions/:id       | 获取单个会话详情      |
| DELETE | /api/sessions/:id       | 删除会话             |
| GET    | /api/templates          | 获取可用模板列表      |

## 8. 关键设计决策

### 8.1 为什么使用 System Prompt 模板而非 Fine-tuning？

- **灵活性**：模板可以随时调整，无需重新训练
- **成本**：无需额外的训练成本和资源
- **可维护性**：添加新文本类型只需新增一个模板文件

### 8.2 为什么用 JSON 文件而非数据库？

- MVP 阶段数据量小，JSON 文件足够
- 零配置，无需安装数据库驱动
- 预留了切换 SQLite 的接口，按需升级

### 8.3 多轮对话的上下文管理

- 保留完整对话历史，不截断
- 每次优化请求携带完整历史，确保上下文连贯
- 对超长对话（>20轮），做智能摘要压缩

## 9. 预期效果

- 用户输入一句话需求 → 3-5 秒内生成高质量文案
- 支持 10+ 种文本类型模板
- 多轮迭代优化，直到用户满意
- 历史会话持久化，随时回顾

## 10. 后续扩展方向（v2）

- 支持流式输出（Streaming）
- 批量生成多版本，用户投票选择
- 自定义模板（用户可保存自己的 Prompt 模板）
- 多语言支持
- A/B 测试：对比不同 Prompt 策略的生成质量
