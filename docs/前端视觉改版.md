# 前端视觉改版 —— 「卷宗」主题

> 只动 `frontend/`，没改任何接口、数据结构或后端逻辑。
> 附带修掉 6 个**能复现的界面缺陷**（见最后一节）。

---

## 1. 为什么改

改造前的界面不是"丑"，是**没有主张**：金色、神秘紫、血红、绿、蓝、橙六个色相同时出现在
按钮、标签、表格行和面板底色上，每一个单看都还行，合起来没有任何一个是**有含义**的。
最要命的是紫色被当成大面积面板底色铺开（`body` 上三层不同色相的径向渐变叠加），
整个界面因此发灰发浑 —— 这正是"几种颜色随便混合一下"的来源。

同时它**没有产品感**：登录页是一张 360px 的深色卡片浮在纯黑上，玩家大厅直接把表单控件
堆在最上面，没有一个字说明"这是什么"。

所以改版先定"这是什么"，再定颜色。

---

## 2. 主题：深夜书桌上的一份案卷

这个产品自己的产物链条就是一份卷宗：
**需求 → 大纲 → 剧本 → 线索 → 对局 → 复盘**。
界面因此围绕一个隐喻组织：

| 层 | 隐喻 | 用在 |
|---|---|---|
| **墨 ink** | 夜里那张书桌 | 应用外壳、页眉、面板、按钮 |
| **纸 paper** | 案卷本身 | 剧本正文、真相、线索文本 |
| **黄铜 brass** | 台灯的光 | 唯一的品牌色与主操作色 |
| **封蜡红 wax** | 那桩命案 | 凶手 / 真相 / 危险 / 指控 |
| **铜绿 verdigris** | 机器那一侧的声音 | AI / NPC / 成功态 |
| **赭黄 amber** | 搜证中的手电 | 警告 / 搜证 |

分工只有一条硬规则：**内容用纸，操作用墨。**
所以剧本、真相、专属复盘都渲染成"纸面"，而所有可点的东西都留在墨色里 ——
读者一眼能分清"哪些是读的、哪些是点的"。

色相从 6 个收到 4 个（黄铜 / 封蜡 / 铜绿 / 赭黄），且每个都有明确职责。
需要新语义时只允许用现有色相的深浅，**不再新增色相**。

`frontend/src/styles/tokens.css` 里保留了旧变量名（`--gold` / `--mystic` / `--blood` / `--surface` …）
作为别名指向新令牌，所以漏改的旧样式不会突然失效；但新代码一律用新令牌。

## 3. 图像素材（本地 ComfyUI 生成）

四张图都用本机 ComfyUI（Qwen-Image 2.1，`D:\dsh\dsh-comfyui.ps1`）生成，
提示词与参数见当时执行脚本；生成后**用 Chrome canvas 转成 WebP** 再入库：

| 文件 | 用途 | PNG → WebP |
|---|---|---|
| `src/assets/art/login-desk.webp` | 登录页整幅背景（雨夜书桌、案卷、黄铜油灯、放大镜） | 914 KB → 40 KB |
| `src/assets/art/bund-night.webp` | 玩家大厅英雄条（外滩雨夜天际线） | 790 KB → 13 KB |
| `src/assets/art/paper.webp` | 纸面纹理（剧本 / 真相 / 线索） | 1 477 KB → 14 KB |
| `src/assets/art/ink.webp` | 墨底颗粒（页面背景叠层） | 555 KB → 3 KB |
| `src/assets/art/game-hall.webp` | 对局页整幅背景（夜里的老宅走廊，尽头一盏灯） | 397 KB → **6 KB** |

合计 **4.1 MB → 77 KB（−98%）**。压缩走的是本机 Chrome 的 canvas 编码，
没有引入任何新依赖。`ink.webp` 只有 3 KB，低于 Vite 的 4 KB 内联阈值，
所以生产构建会把它内联成 data URI —— 服务端 CSP 是 `img-src 'self' data:`，允许。

五张图刻意选在"暖光 + 墨蓝"这一组关系里，等于用一张照片把整套配色**钉死**，
后面所有颜色都是从这张图里取的，而不是各自挑的。

`game-hall.webp` 只有 6 KB，因为这张图本来就是"九成近黑"——
而**这正是它能用的原因**，见第 5 节的"对局背景"。

## 4. 样式结构

改造前是单个 `common.css`：**1 448 行、150 个类，其中 98 个是 React 化之后再没人引用的
旧静态页样式**（书页翻页、NPC 弹窗、旧侧栏…）。混在一起时，"这个类还有没有用"
每次都要重新查一遍。

现在按层切开（`styles/index.css` 是入口，`main.jsx` 只引它）：

```
tokens.css      设计令牌与别名（不含任何选择器规则）
base.css        重置、页面背景、排版、工具类、动画
components.css  面板 / 按钮 / 表单 / 提示 / 标签 / 表格 / 状态
pages.css       应用外壳、登录、大厅、对局视图、管理端
```

越靠下的文件越接近具体页面，死代码一眼可辨。旧静态页的那批样式已删除。

**一个例外**：`public/voice-check.html` 是独立静态页，不经过 Vite 构建，所以它的
`:root` 里内联了一份同样的令牌值 —— 改主界面配色时要记得同步这里（文件顶部有注释提醒）。
它的逻辑放在同级的 `public/voice-check.js`，不能内联（服务端 CSP 是 `script-src 'self'`）。

## 5. 逐页改动要点

**登录页** —— 整幅场景图打底、左侧压暗，卡片压在暗部上（而不是把图调亮再糊一层颜色）；
加了"案"字印章式品牌标记；表单换成全局 `.form-input`，不再写内联样式。

**玩家大厅** —— 顶部加英雄条说清"这是什么"；「加入房间」提到最前（最高频动作）；
剧本 / 活跃房间改成两栏卡片，带角色数、NPC 数、阶段中文名。

**房间大厅** —— 房号从 13px 小字变成整页最醒目的元素（玩家此刻最需要把它发给朋友）；
场景描述限制到 68ch 行宽 + 首行缩进 + 自动分成两段（改造前 1680px 下每行 90+ 字、一屏 8 行密集小字）；
玩家名册改成带座位号的名单；角色选择从小按钮改成角色卡，并**禁掉自己已选的那个**。

**阅读剧本** —— 剧本正文搬上"纸面"：宋体、68ch 行宽、行高 1.95，加一条阅读进度线。
分页/整篇滚动的产品决策保持不变（玩家反馈过分页"内容太少、还会截断"）。

**搜证与讨论** —— 从 `1fr 380px` 内联网格改成 `.game-shell`；
讨论区改成对话流（AI 发言用铜绿左边线区分，不再用紫色气泡）；
**线索从面板底部的附属列表提升为与搜证同一块的"证物"区**，搜到就在下面出现，不用滚动到别处找；
线索编号做成等宽小徽章，发现者右对齐。

**我的剧本抽屉（对局期间常驻）** —— 这是用户反馈的真实缺口：剧本在挂载时就取到了，但**只有阅读阶段**把它渲染出来，一进搜证就再也打不开，于是别人问"你那天几点在哪、
跟谁见过面"时玩家只能凭记忆答。现在页眉常驻一个「📖 我的剧本」按钮（搜证 / 讨论 /
投票 / 复盘全程可用），点开是右侧覆盖式抽屉：

- **覆盖式而不是插回主列**：讨论才是这一阶段的主场，把剧本插进去会把发言挤走；
  玩家的真实动作是"一边看别人说话、一边翻自己的本"，所以让它浮在讨论区之上。
- 宽度 `min(640px, 94vw)`：640px 下正文约 35 个汉字一行，是中文比较舒服的行宽。
- 顶部有**小节跳转**：正文按标题切成 11 个小节（我的时间线 / 案发当日 / 关于某某…），
  点一下就滚过去 —— 四五千字的本子靠滚动找一个名字太慢，这才是"别人问到时"真正省事的地方。
- 含只有本人能看到的「你的秘密」；Esc 可关。

**投票** —— 从一排通用描边按钮改成"指控卡"；补上了缺失的推进入口（见缺陷 4）。

**对局背景（ComfyUI 生成的老宅走廊）** —— 用户要求把对局页背景换成生成的图。
难点不在出图，在于**这一页是高密度信息界面**（发言流 + 线索列表 + 名册）：
背景一旦可辨就会直接吃掉正文可读性，但把面板做成不透明又等于把图盖死（用户明确否掉了这条）。

最后落到的做法是**让同一张图在两种位置受到两种待遇**：

- `.game-bg`：整幅固定背景。生成出来的图本身"九成近黑"，直接用等于看不见，
  所以用 `filter: brightness(5.2)` 把暗部拉起来（用 brightness 而不是 contrast ——
  画面近黑处本来就接近 0，乘系数后仍是 0，黑得下去；而略高于 0 的墙体会被拉成可见的灰。
  `contrast()` 是绕 0.5 中灰转的，对这么暗的图只会把暗部压得更死，方向相反）。
  上面只留一层很轻的暗角。
- `.game-surface .panel`：`background: rgba(21,25,34,.3)` +
  `backdrop-filter: blur(16px) brightness(0.62) saturate(1.1)`。
  **关键在 `backdrop-filter` 里可以放 `brightness()`** —— 它把"面板背后的那张图"压暗。
  于是缝隙里是清晰的场景，面板底下是同一场景的暗化虚影，两者是同一张图。
  `blur` 负责糊掉细节不让纹理和字形打架，`brightness` 负责拿回正文对比度，缺一不可。
- 内层（讨论流 / 卡片 / 线索组）通过 `.game-surface` 作用域内重定义墨阶令牌变半透明，
  但仍比面板更暗，保住"面板 > 卡片"的层级；这几个令牌已确认只用作 background。

参数不是拍的，是**把文字设成透明后采样渲染像素**反推出来的：面板背后实测 0.0079
（对比度 12.2:1，余量太大、图白白被压没了）→ 放宽后约 0.0065~0.014，
对比度仍有 **11.5~12.3:1**（AA 只要求 4.5:1），而背景变得明确可见。

搜证 / 投票 / 真相复盘三个视图共用这一层背景；管理端与大堂完全不走
（已实测：管理端 `hasGameBg:false`、`panelBg:rgb(21,25,34)`、`backdropFilter:none`）。

**真相复盘** —— 做成结案卷宗：一行深红横幅只放凶手名字（一句话结论），
手法 / 动机 / 真相全部上纸面；结算榜改成带名次、细节、总分的行式榜单。

**管理端** —— 统一 `page-head`（标题 + 一句话说明 + 右侧操作）；
六个页签改用真实 `<nav role="tablist">`；用户/模型列表从内联样式表格改成 `.table`
（改造前表格行上有一层紫调渐变，是"颜色乱混"最明显的地方）；生成日志用 `.log-view`；
`OutlinePanel` 接进设计系统，凶手的两条时间线用封蜡红（事实）/ 铜绿（编的）区分。

**语音自检页**（`public/voice-check.html`，独立静态页、不经 Vite 构建）——
配色从一套毫不相干的蓝/绿/红改成与主界面同一套令牌（只能内联，值取自 `tokens.css`，
改主界面配色时要同步）；顺带把它从"生产环境完全不能运行"救回来（见缺陷 10）。

**崩屏**（顶层错误边界）—— 从内联硬编码色改成 `.crash` 类，用封蜡红（出事了，不是品牌露出）。

## 6. 修掉的缺陷（都先复现、再修、再验证）

| # | 缺陷 | 表现 | 处理 |
|---|---|---|---|
| 1 | `var(--dim)` 在 5 个文件里被引用，但 `--dim` **从未定义**，且没写兜底值 | 那些文字颜色整条声明失效，继承到错误的颜色 | 统一改为 `--text-dim`（新令牌体系里不存在"未定义的合法引用"） |
| 2 | `.tag-danger` / `.tag-success` 在 JSX 里用了，CSS 里**根本没定义** | "连接已断开"、"当前生效"、"全员已准备"看起来和普通文字一样 | 在 `components.css` 补齐三个语义标签（含 `.tag-warning`） |
| 3 | PipelinePage 写的是 `className="pipeline-arrow"`，CSS 里定义的是 `.pipe-arrow` | 步骤条箭头没有样式，靠 `→` 字符硬撑 | 统一为 `.pipe-arrow`，并重做成一条连接线 |
| 4 | **投票阶段没有出口**：`showPhaseBar` 只含 `reading/intro/round1/round2`，`VotingView` 自身也没有推进控件；而服务端 `ready` 处理明确允许 voting（只挡 `truth_reveal`/`finished`/`lobby`） | 一桌投完票之后**没有任何办法进入真相复盘**，只能干等 10 分钟兜底超时。旧版实测卡在投票页 150 秒无变化 | `showPhaseBar` 加入 `voting`，按钮文案在投票页改为"提交并查看真相"；实测点击后成功进入 `truth_reveal` |
| 5 | `投票指控（0/0）`：`voteTotal` 只在**有人投过票之后**才由 `vote_update` 带上 | 投票页初看像坏了 | 分母回落到本地可投对象数，并加"已投"标签 |
| 6 | `.stagger > *` 用 `opacity:0 + forwards`，而子元素若自己声明 `animation`（`.state-empty` / `.state-loading`）就会覆盖掉它，且自己的动画没有 `forwards`，播完回到 `opacity:0` | **DOM 里有、屏幕上看不见**。这是本次改版自己踩出来的坑，靠读 `getComputedStyle` 的 `opacity:"0"` 才定位到 | 改成 `animation-fill-mode: backwards`，不再依赖基础透明度 |
| 7 | DM 叙述 / 真相手法 / 专属复盘三处把模型输出的 markdown 当纯文本渲染 | 满屏 `**（详细过程）：`、`*准备工作：*` 原样打出来 | 统一走 `ScriptBody`；并加固 `lib/paginate.mjs` 的 `parseInline`/`classifyLine`：支持整行斜体小标题、清掉**漏写闭合**的标记字符。新增 4 个单测（用例直接取自这次真实的模型输出） |
| 8 | 房主点「开始游戏」后看不到 DM 开场白：`game_started` 把叙述放在 `d.narrative`，PlayerApp 存成 `game._narrative`，但**没有任何地方读它** | 开局的那个人进阅读阶段时少一段正文，其他人正常 | 在 `room_state` 对账 effect 里兜底播种一次，不覆盖后续 `narrative_ready` 推来的完整版本 |
| 9 | 应用**从来没有 favicon** | 每次加载页面，浏览器都会去要 `/favicon.ico` 拿一个 404（生产路径实测的唯一一条控制台错误：`log.error http://localhost:3000/favicon.ico`） | 在 `index.html` 内联一个 SVG data URI 图标（墨底 + 封蜡红印章 + 案）。放文件不行 —— 服务端只从构建产物托管 `/assets`，`public/` 不在其中，放文件会继续 404。服务端 CSP 是 `img-src 'self' data:`，data URI 允许 |
| 10 | **语音自检页在生产环境完全不能用**：`public/voice-check.html` 是一整块内联 `<script>` 加内联 `onclick`，而服务端 CSP 是 `script-src 'self'`（无 `'unsafe-inline'`），两者都被浏览器拒绝执行。而这个页面正是游戏里「打开语音自检页」指向的排查工具，`Dockerfile` 也明确 `COPY public/`，会随镜像发布 | 实测 `http://localhost:3000/voice-check.html`：`#env` 面板一片空白、`window.playVia` 未定义、8 个按钮全部无反应 —— 排查"听不到声音"时拿到的是一个死页面 | 逻辑抽到同源文件 `public/voice-check.js`（`'self'` 放行），内联 `onclick` 全部换成 `data-act` 属性 + 一个事件委托监听器；页面同时改用主界面的「卷宗」配色（原来是一套毫不相干的蓝/绿/红）。复验：`envFilled: true`、`playVia: function`、按钮从 8 个变为 10 个（设备列表渲染出来了） |
| 11 | 自检页版本号自相矛盾：徽章和诊断报告都写 `v5`，正文两处却让用户"确认显示 **v4**" | 一个要求用户核对版本号的页面，自己给了两个互相打架的号 | 版本收敛到一个常量 `PAGE_VERSION`，全部改为 `v5`，"右上角"也改成与实际位置一致的"标题旁边" |
| 12 | **纸面上的 markdown 强调色对比度不足**（本次改版自己引入的）：`ScriptBody` 把标题/加粗写成内联的 `var(--gold-light)`，而同一个渲染器也用在米色纸面上 | 浅金 `#e6c98a` 压在纸色 `#e7ddc6` 上，对比度约 1.3:1 —— 剧本正文的小标题几乎看不见 | 颜色改由 surface 决定：`ScriptBody` 只输出 `.md-*` 类，强调色取 `--md-strong` / `--md-rule`，`.paper-surface` 里覆盖为深墨 `#3a2c12`。实测纸面上 `.md-sub` / `.md-strong` 计算值 = `rgb(58,44,18)`，对比度约 10:1 |
| 13 | **390px 手机上整页横向溢出 26px**（同样是本次改版引入的）：几个栅格写的是内联 `repeat(auto-fit, minmax(400px, 1fr))`，而 `minmax` 的下限是**硬性**的 | 实测 390px 视口下 `scrollWidth 416 / clientWidth 390`，大厅整页可以左右晃 | 收敛成 `.auto-cols` / `.auto-cols-wide` / `.auto-cols-narrow` 三个类，下限写成 `min(400px, 100%)`，窄屏自动退化成一列。复验：390px 下 `hOverflow:false`（390/390），1680px 下大厅仍是两栏 `644px 644px` |

  服务端的 CSP（`img-src 'self' data:` / `script-src 'self'`）。整套流程在
  `http://localhost:3000` 复跑一遍，同样 `consoleProblems: []`，并且：
  四张图的 `background-image` 都真实解析到 `/assets/*.webp`（不是内联兜底、也不是 404）；
  自检页 `envFilled: true` / `playVia: function`；纸面上 `.md-sub` 的计算色 = `rgb(58,44,18)`。

## 8. 明确没做的

- 接口、数据结构、后端逻辑、事件名一律未动。

  （原来用 `alert` 弹房号，关掉就再也找不回去）。

  LSP 会报 hint（改造前就存在），没有顺手删 —— 它们和 `setXxx` 成对出现，
  单独删一半反而更难读。
