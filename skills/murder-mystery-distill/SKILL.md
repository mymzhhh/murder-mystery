# 剧本杀生成与质检（从真实语料蒸馏）

> 用 **19 本真实商业剧本**（A1 档，docx 文本 + 线索也是 docx）蒸出来的写作与验收规范。
> 语料本身不进仓库，分布与结构结论见 `references/`。

## 什么时候用

- 要**生成**一本新的剧本杀（4–6 人、本格推理为主）
- 要**审查**一本已有/新生成的剧本，判断它离真实商业本有多远
- 要把一本外部剧本**导入**成结构化数据（角色本 / 线索 / 真相 / 主持手册）

不适用：情感本（哭本）、机制本（跑团/对战）——本次语料以本格推理为主，那两类规律不同。

## 先记住三个数（否则后面全会跑偏）

| 指标 | 语料中位 | 常见区间 | 警告 |
|---|---|---|---|
| 角色本字数（中位） | **1636** | 0 – 8605 | 别按 344 的 5617 写，那是前 10% 长本 |
| 时间线时刻数（每本） | **11** | 0 – 142 | 0 的本也存在（用别的方式交代时间） |
| 真相/复盘字数 | **657** | 0 – 10443 | 多数本真相很短；长篇复盘是少数派 |

> 这三个数来自 **64 本**（A1 的 19 本 + A2 的 45 本）。两批独立算出来高度一致
> （角色本中位 1729 vs 1541、真相 672 vs 643、时间线 17 vs 10），不是小样本假象。
> 线索类指标只用 A1 的 19 本（A2 的线索是图片/PDF），见 `references/distributions.md`。

完整分布（含每本明细、覆盖率）见 **`references/distributions.md`**。

> ⚠️ 这三条是从**19 本**里统计出来的，和我们早期"对标 344 一本"的结论**相反**：
> 344 是离群值。以中位数为基准、最多向 75 分位靠。

## 语料是怎么组织的（与我们的模板不同，别搞混）

| 内容 | 真实语料的组织方式 | 不要假设 |
|---|---|---|
| 角色本 | **一个角色一个 docx**，标题就是角色名（`占卜师.docx`、`唐•何塞.docx`） | 没有"第N幕"结构（19 本里只有 1 本有） |
| 线索 | **一个 `线索.docx`，按人物分组 + 编号列表**（`唐·何塞` → `1. … 2. …`） | **没有 A1/B1 编号** —— 那是我们自己导入时编的 |
| 隐藏线索 | 线索条目后直接标「（发现隐藏线索，可深入调查）」，紧跟一行「隐藏线索：…」 | 不是独立文件、不是字段 |
| 真相 | 多数**写在手册里**（`真相.docx` 只有少数本有） | 不要因为找不到 `真相.docx` 就认为没真相 |
| 主持手册 | `组织者手册.docx` / `主持人手册.docx` / `游戏说明.docx` | 文件名不统一，得按关键词找 |
| 规则 | 写进手册开头（AP 点数、每轮能搜几次、深入调查也花 AP） | 7/19 本有明确的 AP 规则，其余用别的说法 |
| 图片 | **独立 jpg 文件**，正文里不引用 | 没有 `![](...)` 引用语法 |

详见 **`references/structures.md`**（含真实片段）。

## 写作流程

1. **定骨架**：角色数（4–6）、是否有 NPC、案件发生在第几幕（多数本只有一幕/无分幕）。
2. **写设定集**：时代、地点（3–6 个可搜查场所）、死者、死因、真凶、动机、手法。
3. **写角色本**（每本 900–2500 字，重点给"该角色**知道什么/不知道什么**"）：
   - 我是谁（身份、与死者的关系）
   - 我看到了什么（时间线，**8–20 个时刻**，明确"亲眼所见/听说"）
   - 我隐瞒什么（对自己不利的事实）
   - 我的任务（1–3 条可判定的小目标）
4. **写线索**：按"人物/场所"分组，每组 3–8 条编号条目；每条只说**物证事实**，不写结论。
5. **埋隐藏线索**：挑 2–5 条线索挂「（发现隐藏线索，可深入调查）」，紧跟一行给**更深一层的证据**。
6. **写真相**：真凶 + 手法 + 时间线复盘 + **逐条回扣关键线索**（不是长篇抒情）。
7. **写手册**：开场白（200–800 字氛围）+ 流程 + 规则（AP/搜证次数）+ 结局分支。

## 验收

先跑自动校验，再人读。

```bash
python scripts/validate.py <剧本.md>
```

自动校验覆盖：
- 角色本字数是否落在分布区间（并给出百分位）
- 时间线时刻数、线索条数、真相字数是否落在区间
- 结构不变量：每个角色本都有"时间线"段、线索无结论化表述、隐藏线索有对应更深内容

人读只查三件事（自动查不出来的）：
1. **诡计是否成立**（手法在物理与时间上是否可行）
2. **三处误导是否各自可被证伪**（不是"看起来可疑"，而是"用某条线索能排除"）
3. **只有完整证据才能锁定真凶**（缺一条就定不了案）


## 我们现在的实际位置

`references/baseline-comparison.md` 记录了 2026-10-20 的实测：我们生成的本
**每一项都落在区间内，但稳定在 89–95 百分位**（真实本多在 32–79）。
即"没有越界，但整体偏重"——时间线密度、真相篇幅、手册字数都贴着上限。

三条可操作结论：
1. 手册偏长（唯一超区间项）→ 与语料对比时把"真相"从手册里扣掉再算；
2. 时间线密度贴顶（141/142）→ 下次生成压到 30–60，真实本靠叙述隐含时间；
3. 真相 5627 字是中位的 8 倍 → 4000 字下限保留（防截断），但不要继续加码。

分布测不出"故事好不好"。人读差距集中在：诡计巧妙度、误导的可证伪性、线索克制
（我们的线索常顺带写解释，真本只写事实）。
## 已知失败模式

`references/pitfalls.md` 记录了 11 个**真实踩过的坑**（每个都带检测方法），
包括：角色标题被修订吃掉导致整本少人、真相复盘提取为空、全部线索变成"可深入调查"、
线索缺地点导致永远搜不到、配图往画面里写乱码字 等。

生成后**逐条对照**，这些坑我们全部踩过至少一次。
