# 语义评审标准（rubric）

自动校验能查的：编号对不对、算术对不对、地点在不在、时间线落没落地。
**查不了的**：诡计成不成立、误导能不能被排除、线索有没有写结论、是否只有完整证据才能定案。

这份 rubric 就是补这四项。它**不自动打分**——`scripts/review_packet.py` 负责把判断所需的
原文片段抽成"评审包"，评审者（人，或带证据要求的模型）按下面的锚点打分，**每个分数必须附引用**。

> 为什么必须附引用：不附引用的评分会退化成"感觉不错/感觉一般"。今天的语料里每一处
> 都是可定位的（线索有编号、时间线有时刻、真相有段落），所以"说不出在哪"就等于"没这回事"。

---

## 维度一：诡计成立性（0–3）

**问题**：这个手法在物理与时间上做得到吗？

| 分 | 锚点 |
|---|---|
| 3 | 手法每一步都可在原文找到**物证或观察**支撑；换掉任何一条线索，手法就解释不通 |
| 2 | 手法可成立，但有 1 处依赖"恰好没人在场/恰好没注意"，原文没给支撑 |
| 1 | 核心步骤缺少物理可能性（如：隔着房间听见低声对话、时间不够走完路径） |
| 0 | 手法与死因/现场描述矛盾 |

**必须引用**：手法的每个步骤 → 对应线索编号或时间线条目。

**常见失败**：
- 凶手在 A 处动手，但该处线索只写了"地面积灰"，从未提到凶器
- 时间线给了 5 分钟做需要 20 分钟的事
- 死因写"中毒"，但毒物线索出现在一个从未被接触过的房间

---

## 维度二：误导的可证伪性（0–3）

**问题**：每条"看起来像凶手"的误导，能否被**某条具体线索排除**？

| 分 | 锚点 |
|---|---|
| 3 | 每条误导都有**至少一条线索能排除**，且排除理由不依赖凶手的自白 |
| 2 | 多数误导可排除，但有 1 条只能靠"没人提过"来维持 |
| 1 | 误导靠"角色不说"维持，玩家无法通过搜证推翻 |
| 0 | 误导与真相其实是同一件事（等于没有误导，或真相和线索打架） |

**必须引用**：误导线索编号 → 排除它的线索编号（成对列出）。

**常见失败**：
- 误导是"某人被看到离开房间"，但没有任何线索能说明他离开后去了哪
- 三条误导全部指向同一行为（比如都在说"他欠钱"），实际只有一条在起作用

---

## 维度三：线索的克制（0–3）

**问题**：线索是"事实"还是"结论"？

| 分 | 锚点 |
|---|---|
| 3 | 线索只陈述可观测事实（物件、位置、痕迹、证词原话），判断留给玩家 |
| 2 | 少数线索带轻微解释，但不点破 |
| 1 | 多条线索直接写结论（"说明他是凶手""证明他撒了谎"） |
| 0 | 线索里直接点名凶手或复述真相 |

**自动可测部分**：线索段落里出现"说明/证明/表明/可见/因此"的次数
（`validate.py` 已有弱检查，阈值 ≤2）。

**必须引用**：越界的线索编号 + 那句话原文。

---

## 维度四：唯一锁定（0–3）

**问题**：是否"只有拿全证据才能定案"？还是"少一条也能猜对"？

| 分 | 锚点 |
|---|---|
| 3 | 缺任意一条关键线索，就无法把凶手与其他人区分开 |
| 2 | 缺 1 条仍能推出，但会剩下 2 个候选 |
| 1 | 只凭 1–2 条线索就能锁定（玩家会"秒破"，体验差） |
| 0 | 拿全线索也无法排除其他人（案子不成立） |

**必须引用**：定位凶手所必需的线索编号清单；以及"去掉这条会怎样"。

## 打分表（每次评审都要填）

| 维度 | 分数 | 依据（线索编号 / 时间线时刻 / 段落） |
|---|---|---|
| 一、诡计成立性 | /3 | |
| 二、误导可证伪性 | /3 | |
| 三、线索克制 | /3 | |
| 四、唯一锁定 | /3 | |
| **合计** | /12 | |

参考基线：抽 3 本真实语料按同一标准自评，大致落在 **8–11 分**。
我们最新的《雨覆孤台》实测 **10 分**（范例见 `review-example.md`）——即物证链这一层已达真本区间；
真正的差距在"诡计的意外性"，这一点本 rubric 测不出来。

## 怎么用

```bash
# 1. 先抽评审包（把需要的原文都摊在面前）
python scripts/review_packet.py <剧本.md>

# 2. 再按上面的锚点逐项打分，每项写引用

# 3. 分数 <8 的项，回到 SKILL.md 的写作流程对应步骤重写
```

评审包里会自动给出三类**预标记**，它们是自动可测的线索，但不能代替判断：
- 手法声明缺失 / 未落地（同 `logic-checks` 的规则）
- 线索里的结论化措辞（"说明/证明"等）
- 隐藏线索与父线索的配对是否成对出现
