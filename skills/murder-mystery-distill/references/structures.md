# 结构规范（从 19 本真实语料归纳）

每一条都标注了**证据**（出自哪本、什么形态），以及**反例**（不成立的情况）。
摘录只保留结构骨架，不复刻原文。

---

## 1. 角色本：一个角色一个文件，标题就是角色名

**证据**：`344` 有 `占卜师.docx` / `唐•何塞.docx` / `旅人.docx` / `米里奥.docx`；
`008-死亡致意` 是 `1601 约翰.docx` / `清洁工 乔治.docx`（带序号前缀）。

**因此**：解析角色本要按"文件名即角色名"，不能靠正文里的 `### 玩家角色 N：`。
**反例**：`036-上海滩事件` 只交出 1 个角色本文件（其他角色内容并进了别处），
所以"角色本份数"会低估——判断角色数应以剧本名里的"（N人）"和正文提及为准。

### 角色本的三段式

多数本的结构是：**我是谁 → 第一幕（事件/时间线）→ 任务/须知**。
`344` 的角色本开头写得很典型：

```
【第一幕 初识】
我是塞维利亚的一名占卜师，平时穿着一件黑色的长袍……
建议隐瞒剧情：
我的记忆开始于十年前的一艘小船之上……
```

要点：
- **`建议隐瞒剧情：`** 这种显式标记是给玩家看的"你不能说的事"，比"你有秘密"具体得多。
- 时间不写在标题里，而是散在叙述里（"今年虽然只有二十多岁"）。
- 19 本里只有 `344` 有 `【第一幕】`/`【第五幕】`，**分幕是少数派**（1/19）。

## 2. 时间线：多数本不叫"时间线"

**证据**：19 本里只有 15 本能数到时刻，中位 17 个；`030-美术室` 高达 142 个。
`344` 的写法是把时刻嵌在叙述里（"案发当天卡门毒发的时间为23：35，16分钟后……"）。
`146-盛典前夜` 则用密集的 `HH:MM` 条目。

**因此**：
- **不要强制"每个人必须有时间线段"** —— 只有 15/19 有；
- 但**时刻必须可核对**：凶手的手法时刻要能在自己的叙述里找到对应动作。

**反例**：`060-魔盗之殇` / `355-聆听阁` / `008-死亡致意` / `190-红楼梦中人` 数到 0 个时刻
——它们用"第一轮/第二轮"或相对顺序交代时间。这不算缺陷。

## 3. 线索：按人物分组 + 编号列表（**没有 A1/B1**）

**证据**：`344` 的 `线索.docx` 全文结构：

```
唐·何塞
1. 唐·何塞穿着一身骑士的军装，五官端正、气宇不凡
2. 行囊里一枚红宝石戒指
3. 口袋里有一朵枯萎的玫瑰
……
米里奥
1. 口袋里有一只空瓶。（发现隐藏线索，可深入调查）
隐藏线索：瓶壁上残留着微量红色粉末
2. 一只破碎的怀表。（发现隐藏线索，可深入调查）
```

要点：
- **分组标题 = 人物名**（也有按场所分组的本，如 `039` 用"第N轮的秘密线索"分页）。
- 每条线索是**一句事实**，不带推论（"口袋里有空瓶"，不写"说明他下过毒"）。
- 编号是**组内序号**，跨组重来（每个人从 1 开始）。

**反例**：`039-愤怒的葡萄` 用 `第N轮的秘密线索 + ———按这条线折叠———` 的分页式排版，
编号条目数为 0，但线索齐全（6 轮）。**所以"线索条数"只能当参考，不能当质量门槛。**

---

## 4. 隐藏线索：内联标记，紧跟一行"隐藏线索："

**证据**：`344` 有 16 处标记，形态固定：

```
1. 口袋里有一只空瓶。（发现隐藏线索，可深入调查）
隐藏线索：瓶壁上残留着微量红色粉末
```

**因此**：
- 隐藏线索是**父线索的下一行**，不是独立文件、不是字段；
- 玩家先拿到父线索，选择"深入调查"才拿到那一行；
- 4/19 本有这种标记，其余本没有隐藏机制 —— 这是**加分项不是必需项**。

## 5. 真相：多数写在手册里，篇幅普遍不长

**证据**：只有少数本有独立 `真相.docx`（`344` 的 10443 字是极值）；
17/19 本能量到真相，**中位仅 672 字**。

典型真相结构（`344` 的骨架）：

```
一、案情分析      ← 死因鉴定（哪种伤致命、为什么）
二、背景还原      ← 每个人与死者的关系、动机
三、动机分析
四、支线任务一览
五、（真假）结局
附录、客观时间线一览
```

要点：**真相是"解谜说明书"，不是小说**。每段都在回答"为什么不是别人"。

**反例**：很多本真相只有几百字（`156-红影` 672、`144-万灵血` 640），
把篇幅放在"逐条排除嫌疑人"上，而不是抒情。

## 6. 手册：文件名不统一，规则写在开头

**证据**：`组织者手册.docx`（344）/ `1主持人、规则相关（主持人需要提前阅读）.docx`（039）/
`游戏说明.docx`（024）/ `探长 修斯（组织者手册，组织者提前阅读）.docx`（008）。

规则段（`344` 原文骨架，只留结构）：

```
每人11点AP，第一轮每位玩家可以使用5点AP，第二轮每位玩家可以使用6点AP。
搜索一次耗费1点。有些地点会注明可以深入调查，深入调查每次仍需耗费1点AP，自己不可以搜查自己。
一条线索只能被查看一次……
第二轮搜证开始时请公开第五幕给所有玩家。
投票之前所有玩家填写答卷，之后再投票。
```

要点：
- **AP 点数 + 每轮上限 + 单次消耗 + 深入调查也消耗**，这四件必须写清；
- 7/19 本有明确 AP 规则，其余用"搜N次"等说法；
- 手册开头通常是**DM 开场用的散文**（`344` 818 字，`039` 4983 字）。

## 7. 图片：独立文件，正文不引用

**证据**：`344` 目录里有 22 张 jpg（线索卡/角色图/地图），但 docx 正文**没有任何图片引用**。

**因此**：`![](...)` 式引用是**我方模板的机制**，不是商业本的做法。
用不用取决于目标平台：如果玩家要在网页上看图，引用是必要的；如果只做语料蒸馏，不要把它当规范。

---

## 8. 总结表：语料惯例 vs 我方模板

| 项目 | 语料惯例 | 我方模板 | 谁对 |
|---|---|---|---|
| 线索编号 | 组内 `1. 2. 3.` | `A1/B1` 全局编号 | 语料惯例（全局编号是我们加的） |
| 隐藏线索 | 内联「（发现隐藏线索）」+ 下一行 | `hiddenContent` / `hiddenBehind` 字段 | 语料惯例（字段是我们的映射） |
| 地点 | 多数没有结构化地点字段 | 每条线索带 `location` | 需要看平台：网页搜证必须有地点 |
| 真相 | 多在手册内、篇幅短 | 独立 `真相复盘` 段、有字数下限 | 语料惯例（但我们的下限是为了防截断，另有原因） |
| 分幕 | 1/19 | 支持多幕 | 语料惯例（分幕是少数派） |
| 图片引用 | 无 | `img:` 引用 | 平台需要 |
